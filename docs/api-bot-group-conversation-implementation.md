核对日期：2026-09-27。依据[产品方案](api-bot-group-conversation-proposal.md)、[评审意见](api-bot-group-conversation-review.md)及当前工作区代码。

## 当前结论

**Bot 会谈主流程已接入，凭据保护、流式显示、会谈切换、原请求重试和稳定排序已修复并通过对应自动测试；完整 MVP 尚未验收。**

Bot 会谈直接替代旧 API 分屏，保留“内嵌官网 / Bot 会谈”两个入口；中英文入口名称已统一。API 地址、Key 和模型是服务配置。旧 API 格子的内部调用分支仍待清理，保留迁移所需配置后再移除。

Bot 现在支持本地 CLI Agent 与独立 API 配置，允许混合会谈。自动主持、完整终端和自动批准文件/命令权限不属于本轮范围。以下描述未提交工作区，不代表已发布版本。

## 本地 Agent 与自定义 API（2026-09-27）

- 本地目录：Codex CLI、Claude Code、Gemini CLI、Qwen Code、Kimi Code CLI、Qoder CN CLI；提供官方安装命令、打开系统终端安装、复制命令、安装指南和重新检测。
- 首次创建 Bot 时扫描本机，已安装项优先列出，未安装项各自提供“一键安装”。安装在系统终端完成，返回应用后由用户点击“重新检测”刷新；安装未完成或无法启动时不能创建可用成员。安装失败可重新打开安装终端。
- 首次扫描后保存安装路径和检测结果。重启、重复打开、切换窗口、安装或登录返回、运行失败均不自动扫描；后续统一由用户点击“重新检测”。登录凭据不写入缓存文件，主动登录前仍实时确认已有登录，防止重复授权。
- macOS/Linux 检测与运行沿用登录终端的 PATH，覆盖 nvm 等用户目录安装；安装后的检测会重新读取路径。
- 自定义 API 预设：DeepSeek、Qwen、Kimi、GLM、豆包、OpenAI、OpenRouter；选择服务商后自动填入地址和模型，填写 Key 即可创建 Bot；模型下拉最多展示 3 个近期文本模型，不足 3 个时按实际数量展示。可切换自定义地址或手动填写模型 ID，Key 使用系统安全存储加密。预设是接入起点，不保证账号权限或所有平台特性。
- Bot、会谈成员与重试请求保存接入快照；更新模板不修改旧会谈。新消息记录当时的运行来源。旧共享 API 配置继续兼容。
- CLI 不经过 API 调用或全局 Key 检查。Codex 逐段显示回答，无需等待整条消息生成完毕，Claude 使用无工具的非交互请求；Gemini/Qwen/Kimi/Qoder CN 使用 ACP，新建独立会话、接收回答文本、拒绝权限请求。没有启用自动批准工具的参数。
- 自动使用检测到的本地 Agent，可选择模型；模型留空沿用 CLI 配置。已有登录直接复用，首次使用保留终端登录入口；Codex 和 Claude 在登录前重新检查状态，已登录时跳过，状态不明确时先检查配置。检测区分未安装、可启动、登录已知/未知；没有专用登录状态检查的 CLI 不伪称已登录。
- 新增受控子进程测试覆盖五种入口、协议解析、拒绝权限、取消和错误过滤；服务测试覆盖 CLI/API 混合会谈与独立凭据；真实 Electron 渲染测试覆盖目录、安装入口调用和无全局 Key 创建本地 Bot。
- Codex 官方服务在应用内使用 HTTPS 流式连接，继续复用本机登录和默认模型；此选择仅作用于当前会谈请求，不修改本机 Codex 配置，自定义服务商保持原配置。真实账号短提示对比：默认连接约 68 秒完成并多次断流重试，HTTPS 约 9 秒完成且无重试；该结果不代表复杂回答的固定耗时。
- 已执行 Codex 真实账号短提示验证；尚未执行真实安装或五个 CLI 的完整端到端验收。终端安装流程依赖本机系统终端及官方安装所需环境；Windows/Linux 真实安装与打包仍待验收。

## Bot 身份与实际能力

- 名称和 Soul 定义 Bot 的职责、风格和行为规则，不改变底层模型、登录方式、工具或权限。
- 本地 Agent 复用已有登录；API Bot 使用所属服务商的 API Key。使用 OpenAI 模型不等于使用本机 Codex 登录，回答旁直接显示实际接入来源。
- 每次新提问提供当前本机时间与时区。API 会谈目前没有联网搜索工具，Soul 可以要求不编造热点，但不能赋予联网能力。
- API 最大输出默认 4096 tokens，可在 Bot 设置中调整。它是输出上限，不是价格承诺；余额不足仍可能失败。
- 修改模板只影响新会谈，已有成员保留接入快照。若希望小 T 使用本机 Codex，应选择本地 Codex Bot 创建会谈；不会自动把现有 API Bot 替换为本地 Agent。
- 额度不足和 API Key 无效使用不同提示，不引导用户重新登录本机 Codex。原始错误可展开查看，处理原因后可重试。

## 使用顺序

1. “管理 Bot”只列出已保存的 Bot，可编辑或删除；“创建 Bot”打开独立表单，自动扫描本地 Agent；已登录的直接复用，首次使用可登录。
2. 也可选择“自定义 API”，选择服务商、填写 API Key、选择模型并创建 Bot。
3. 从管理列表进入的新建或编辑，完成或取消后返回列表；独立打开创建页，完成或取消后返回原会谈页面。取消不保存。创建好 Bot 后点击“新建会谈”，勾选 一个或多个 Bot。本地 Agent 和 API Bot 可以混合。
4. 输入一个问题，默认发送给会谈中全部 Bot；各方独立回答，一个失败不阻塞其他成员。

模型清单核对于 2026-09-27，是该日期的近期模型列表，不会自动更新，也不代表账号已开通所有模型。DeepSeek 当前只展示官方列出的两个有效模型，OpenRouter 按上架时间取近期文本模型，排除路由工具。服务商和模型资料见 [DeepSeek](https://api-docs.deepseek.com/api/list-models/)、[Qwen](https://help.aliyun.com/zh/model-studio/models)、[Kimi](https://platform.kimi.com/docs/get-api-key)、[GLM](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)、[豆包](https://docs.volcengine.com/docs/ark/model-list?lang=zh)、[OpenAI](https://developers.openai.com/api/docs/models)、[OpenRouter](https://openrouter.ai/api/v1/models)。

## 已完成修复

| 问题 | 当前行为 | 验证 |
|---|---|---|
| 更换地址复用旧 Key | 地址变化时不再向新地址发送旧凭据；新 Key 留空会清除旧 Key 和旧模型发现结果；配置界面提示影响范围 | 拦截请求验证同地址保留、更换地址清除、明确填写新 Key 三种路径 |
| 流式消息缺少占位 | 开始事件先发送有序消息占位，再推送各成员增量；结束事件同步最终记录 | 服务层验证事件顺序；真实 Electron 渲染验证完成前可见流式文字 |
| 后台会谈覆盖当前会谈 | 当前选择限制显示更新；过期读取被丢弃；草稿、收件人、引用、错误与发送状态按会谈隔离 | Electron 渲染验证 A 完成时 B 保持选中、B 草稿保留、发送目标正确、延迟读取不覆盖当前视图 |
| 重试使用错误操作和配置 | 绑定具体失败消息及最新轮，保存原模型、角色和完整请求上下文；总结、互评沿用原请求；重复/旧轮/成功消息重试被拒绝 | 服务层覆盖总结、互评、配置修改、重启、服务地址变化和无效重试不产生调用 |
| 同毫秒消息乱序 | 本地库增加稳定序号，按插入顺序读取；上下文不再按随机 UUID 重排 | 固定时间测试用户问题先于回答、最新轮正确；旧库自动增量迁移保留记录 |
| 异常及晚到响应 | 单成员异常独立收尾；删除或退出后忽略旧请求增量和结果；事件目标不重复登记 | 模拟异常、删除中的请求与迟到数据测试 |

请求快照只保存在主进程的会谈库中，不含 Key，不通过会谈读取接口发送给界面。没有快照的旧失败消息不能精确重试，会要求重新发送；服务地址变更后，也不能将旧请求通过“重试”发往新平台。

本地数据库通过打开时的增量迁移添加序号与请求快照字段；测试已在临时旧格式数据库上执行迁移与重开检查，没有修改用户实际会谈库。

## 剩余缺口

### 上下文预算与范围提示

当前最新轮仍会整体保留，即使它本身超过预算；预算未完整计入请求开销，成本计算也未按实际语言渲染。`historyScopeText` 尚未呈现在界面；互评/总结前没有缺席或不完整回答的范围确认。

下一步应定义单轮超限处理，保证各成员读取相同历史范围，向用户和模型同时说明裁切、缺席和显式引用的处理，避免静默改变讨论材料。

### 产品流程

- 会谈重命名有后端接口，缺界面入口。
- 总结可复制，尚不能保存 `.md`；自动导入记忆仍是后续能力。
- 互评界面目前发给全体，缺参与成员选择；尚无 @ 候选列表。
- 管理成员显示当前成员并支持移除；点击“添加成员”后选择尚未加入的 Bot，可一次选择多个。仅当没有可选 Bot 时显示创建入口，创建或取消后回到选择页。成员沿用加入会谈时的模型和角色，不在这里编辑 Bot 配置。
- 缺少同模型角色提示、首次发送的数据使用说明、删除范围说明和用量展示。
- 新消息已保存当时运行来源；旧消息无法反推来源时显示未记录，不伪造历史平台。
- 迁移缺逐项可编辑草稿及中途失败恢复验证。
- 窄窗口使用顶部横向列表，尚非方案中的抽屉。

### 生命周期与旧路径

单成员/整轮停止、切换官网再返回、关闭窗口重开、真实平台错误分类仍需补充完整桌面验收。旧 API 格子分支、类型和 IPC 仍存在；清理时须保留原服务配置、凭据和迁移入口。
