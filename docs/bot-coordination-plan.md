# @ 指定回答与总指挥模式

## 指定回答

- 输入 `@` 选择当前会谈成员，支持多选及 `@全体`。
- 明确 @ 的成员优先于顶部的接收者选择，也优先于总指挥模式。
- 邮箱、链接、代码和引用中的 @ 不作为点名；无效成员不允许误发给全体。
- 同名成员在选择列表中附带标识，避免发给错误的 Bot。
- 被指定的 Bot 读取当前会谈历史；没有被指定的成员不发起请求。

## 总指挥

- 在会谈中选择一位已有 Bot 担任总指挥；默认关闭，选择按会谈保存在本机。
- 未明确指定接收者时，总指挥理解任务，根据成员职责安排工作。
- 第一版采用有限流程：一次安排、成员执行、总指挥汇总；最多安排 6 位成员，每人执行一次。
- 独立任务并行执行；有依赖的任务依次执行，后续成员能看到前面的结果。
- 简单任务由总指挥直接回答，不强行安排其他成员。
- 页面显示安排、执行和汇总进度，用户可停止整个流程。
- 安排失败、格式无效或执行失败时不无限重试。保留已收到的回答，并明确告知结果不完整。
- @ 指定回答不经过总指挥；总指挥模式会产生额外模型调用，使用其自身账号或 API 配置。
- 不自动发起成员之间的无限互评，不增加新的账号或全局 API 配置。

## 验证

覆盖点名优先级、同名与无效成员、历史传递、并行和顺序执行、停止、失败、上限、会谈隔离和重启后的配置保留。完成后运行相关自动化测试、界面测试、类型检查及生产构建。
